# Planning & Strategy Context

This workspace is for high-level thinking, architectural decisions, and detailed implementation plans.

## Documentation Types

- **Specs:** Detailed functional requirements for new features (`/docs/specs/`).
- **Plans:** Step-by-step implementation strategies (`/docs/plans/`).
- **Decisions:** Architectural records and reasoning.

## Process

1. **Brainstorm:** Use the `brainstorming` skill to explore intent.
2. **Design:** Create a spec file following the project's high-fidelity standards.
3. **Plan:** Draft an implementation plan before writing any code.
4. **Review:** Ensure the plan aligns with the "Local-First" and "High-Fidelity" mandates.

## Standards

- **Naming:** `YYYY-MM-DD-short-description.md`
- **Format:** Markdown with clear headers and mermaid diagrams where helpful.
- **Integrity:** Plans must include a verification/testing section.
